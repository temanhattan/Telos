# Second-Pass Evidence Verification: V1 Plugin Capability Audit

> **Date:** 2026-08-31
> **Type:** Verification Report
> **Focus:** Rigorous source tracing of audit findings

## 1. Finding-by-finding Verification

### Finding 1: Capture Plugin Staging Failure
- **Claim:** Capture plugins receive `EACCES` because their dynamic `ArtifactLocation` is not passed to Landlock `WritePaths`.
- **Source Trace:** `docs/05_Plugin_API.md` states "the plugin writes the artifact to a staging location designated by the Plugin Host in the request context." However, the `CaptureRequest` schema (line 306) **omits** any such staging location field. Consequently, `host.go` (line 282, `InvokeSandboxed`) merely passes the JSON-marshaled request to the sandbox, and `buildPolicy` (line 308) builds the `WritePaths` statically from `Manifest.FilesystemWrite` (which is empty for Capture plugins, correctly enforced at line 155). 
- **Security Boundary:** Because `ArtifactLocation` is a logical type currently missing from the request schema, the host cannot simply "dynamically append the request's ArtifactLocation to Policy.WritePaths" as previously proposed. Doing so blindly from a plugin response would be a severe path-traversal vulnerability. A trusted staging location must be generated by the Core/Host, placed into the request, and authorized via `Policy.WritePaths`.
- **Verdict:** **CONFIRMED BUG** / **DESIGN-BY-DOCUMENTATION**. The documentation specifies a mechanism that the schema and implementation entirely lack.

### Finding 2: Subprocess Declaration Ignored
- **Claim:** The `permissions.subprocess` list from the manifest is parsed but dropped in `buildPolicy`, blocking legitimate binaries.
- **Source Trace:** `host.go` (line 173) correctly maps `mf.Permissions.Subprocess` to the `Plugin` struct. However, `buildPolicy` (line 308) explicitly hardcodes `Executables: []string{p.Executable}`, completely ignoring the `Subprocesses` field. `sandbox_linux.go` (line 262) strictly bounds execution rights to these `Executables`.
- **Security Boundary:** The docs specify subprocesses by binary name (e.g., `["apt"]`). `sandbox_linux.go` passes the string directly to `unix.Open` (line 290) in `landlockAddPathRule`. Blindly appending the manifest strings to `Policy.Executables` would allow arbitrary path execution (e.g., `../../../bin/sh`) or fail to resolve binaries in `$PATH`.
- **Verdict:** **CONFIRMED BUG**. A secure translation must validate that the declared string contains no path separators, resolve it to an absolute path via `exec.LookPath`, and pass the absolute path to the sandbox policy.

### Finding 3: Unauthorized Network Access (Discovery/Capture)
- **Claim:** Manifest validation fails to reject `Network: true` for offline-only plugin types.
- **Source Trace:** `docs/05_Plugin_API.md` strictly prohibits network access for Discovery, Classification, and Capture plugins. `host.go` (line 152) validates `FilesystemWrite` restrictions, and line 158 validates `ClassificationRule` restrictions. There is **no validation** for `Network` restrictions for Discovery or Capture plugins.
- **Verdict:** **CONFIRMED BUG (Security Gap)**. A minimal manifest for a Discovery plugin with `permissions.network: true` will be loaded, registered, and granted the host network namespace. 

### Finding 4: Stderr / Resource Exhaustion
- **Claim:** Non-sandboxed invocations read `Stderr` into an unbounded `bytes.Buffer`, exposing the host to memory exhaustion DOS.
- **Source Trace:** `host.go` `Invoke` (line 233) initializes `var stderr bytes.Buffer` and assigns it to `cmd.Stderr`. The plugin's stderr output streams into memory unboundedly until process exit. Conversely, `sandbox_linux.go` `Exec` (line 95) explicitly limits stderr to 1MB using `limitedBuffer`.
- **Verdict:** **CONFIRMED BUG (Security Gap)** in the fallback execution path.

### Finding 5: Resource Limits
- **Claim:** `prlimit` constraints are implemented but untested.
- **Source Trace:** `sandbox_linux.go` (line 337) implements `applyResourceLimits` for `RLIMIT_AS`, `RLIMIT_NPROC`, and `RLIMIT_FSIZE`. However, a trace of `host.go` `buildPolicy` reveals these policy fields (`MemoryBytes`, `MaxProcesses`, `MaxFileSizeBytes`) are **never populated** by the host. They are permanently zero.
- **Verdict:** **CONFIRMED BUG (Functional/Security Gap)**. The limits are dead code because the host never sets them. Furthermore, they are missing runtime integration tests.

### Finding 6: Protocol Robustness
- **Claim:** Missing test coverage for protocol handling.
- **Source Trace:** `host.go` line 258 handles malformed JSON safely (`json.Unmarshal`). `limitedWriter` safely truncates oversized output. `context.WithTimeout` safely kills the process. However, `host_test.go` and `sandbox_integration_test.go` contain **no tests** exercising timeouts, oversized output, malformed JSON, or stderr flooding.
- **Verdict:** **TEST GAP**. The implementation is robust but lacks verification.
